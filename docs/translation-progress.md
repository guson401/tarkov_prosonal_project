## 확인된 주의점

- `scripts/translate-tarkov-quests-offline.py`는 파일명과 최종 메타데이터에는 Argos라고 쓰여 있지만, 실제 추론 엔진은 `facebook/nllb-200-distilled-600M` 및 PyTorch입니다. 코어 수의 절반을 쓰도록 설정되어 있어 Python CPU 사용량이 커질 수 있습니다.
- 이 스크립트는 모델을 `local_files_only=True`로 불러옵니다. 모델 파일이 로컬 캐시에 없으면 다운로드하지 않고 오류가 나야 하므로, 이 스크립트의 정상적인 추론은 네트워크 사용 원인이 아닙니다.
- 현재 체크포인트에는 `engine` 필드가 없습니다. 스크립트는 모델 이름이 체크포인트의 `engine`과 일치할 때만 재사용하므로 현재 두 항목은 재사용하지 않고, 이미 본문 번역이 끝난 23개를 제외한 914개를 대기 작업으로 계산합니다.
- 별도 파일 `scripts/translate-tarkov-quests.mjs`는 Google Cloud Translation API에 요청하는 온라인 번역기입니다. 오프라인 번역과 혼동해 실행하지 않도록 주의하세요.

## 실행 및 재개

오프라인 번역은 프로젝트 루트에서 실행합니다.

```powershell
python scripts/translate-tarkov-quests-offline.py
```

번역 결과는 퀘스트 단위로 체크포인트 파일에 저장되고, 콘솔에는 10개마다 진행 상황이 출력됩니다. 인자를 주면 해당 개수만 처리하는 제한 실행입니다.

```powershell
python scripts/translate-tarkov-quests-offline.py 10
```

네트워크 급증을 감시하며 실행하려면 다음을 사용합니다. 전체 네트워크가 50 Mbps 이상인 상태가 3초 연속 이어지면 번역을 중단합니다. 50 Mbps를 한 번이라도 넘으면 당시 TCP/UDP 소켓 소유 프로세스와 PID를 `%TEMP%\tarkov-translation-monitor-*` 로그에 기록합니다. 이미 끝난 퀘스트의 체크포인트는 유지되며, 진행 중이던 퀘스트는 재개 시 다시 처리될 수 있습니다. 이미 실행 중인 번역 프로세스에 감시기를 연결하려면 `-AttachProcessId <PID>`를 지정합니다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run-monitored-offline-translation.ps1
```

진행 수를 다시 확인하려면 다음 명령을 사용합니다.

```powershell
python -c "import json,pathlib; d=json.load(open('resources/quests/quests.en.json', encoding='utf-8')); c=json.load(open('resources/quests/quests.argos-cache.json', encoding='utf-8')) if pathlib.Path('resources/quests/quests.argos-cache.json').exists() else {'quests':{}}; q=d['quests']; print('본문 완료', sum(bool(x.get('sectionsKo')) for x in q), '/', len(q), '| 제목 번역', sum(bool(x.get('titleKo')) for x in q), '/', len(q), '| 체크포인트', len(c.get('quests', {})))"
```

## 네트워크 제한 요청 상태

VS Code와 Python의 대역폭을 각각 25 Mbps로 제한해 합산 약 50 Mbps 이내로 맞추려 했으나, Windows QoS 정책 등록이 실패했습니다. 영구 저장소는 `네트워크 경로를 찾을 수 없음`, 현재 세션 저장소는 `액세스 거부`를 반환했습니다. 따라서 현재 적용된 제한은 없습니다.
